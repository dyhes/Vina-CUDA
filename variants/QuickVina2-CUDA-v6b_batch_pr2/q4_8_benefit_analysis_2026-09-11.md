# Q4-8 完全根治的收益与成本分析（诚实版）— 2026-09-11

## 直接回答

**完全根治没有任何性能收益——反而可能略微变慢。** 它买到的是三样
“科学工程品质”：

### 买到的

1. **位级可复现**：同 seed = 同 PDBQT 字节输出。当前只能做到 mode1
   稳定、mode2-9 分布一致。论文审稿人若要求“给我可复现的输出”，
   现状答不上来
2. **精确 A/B 测试能力**：现在任何优化改动都必须跑 CASF 全量 + 分布
   比较（MC 噪声底 ~0.16/Top-1 极差 13）；若确定性，**diff 两个输出
   文件即可判定改动影响**——未来优化的验证成本从“10 分钟全量”降到
   “秒级 diff”。这是对**后续所有优化迭代**的复利
3. **回归测试可行性**：CI/回归门禁需要确定性；没有它，只能靠统计
   门禁（噪声带），弱得多

### 买不到的

- 性能：非原子累加比 atomic 更快；修复 = 加同步 = 略慢（Q4-8 部分修复
  已付过：色循环 + syncs，全量认证 k2 0.125→0.125，成本≈0 但也没赚）
- 精度/质量：结果本就在噪声带内

### 成本

- 工程：racecheck 72 报告全清（mutate 49 + 散布 23），跨 eval 同步
  补全——涉及 LS/BFGS 热路径，Q4-3 教训表明这类改动必须 design-first
- 运行时：新增 syncs 估计 k2 +1~3%（1pxn 冒烟可验证）

## 决策矩阵

| 情形 | 建议 |
|---|---|
| 论文只报性能+精度分布 | **不必根治**：多跑中位口径已足够防御 |
| 后续还有多轮 kernel 优化迭代 | **值得**：精确 A/B 的复利 > 一次性成本 |
| 审稿人要求可复现性 | **必须**（或声明变异来源+分布口径）|
| v6-batch 合并前 | **强烈建议**：batch 改动大，没有确定性基准无法精确归因 batch 增量 |

## 我的建议

**推迟到 Q4-7 v6-batch 合并之后、下一轮 kernel 优化开始之前做。**
理由：当前 Q4-6/Q4-7 认证已完成（分布口径），即将到来的 v6-batch
合并是最大改动——若先根治确定性，batch 的增量可以用 diff 精确验证；
若不根治，batch 认证还是得走全量分布比较。但根治本身 1-2 个会话，
现在做会推迟 batch 落地。

顺序建议：Q4-7(v6-batch 合并) → Q4-8(确定性根治) → 之后的优化
全部享受精确 A/B。
