# Q4-8 结果修正（重要）：-50% k2 的归因错误 — 2026-09-11

> 用户质疑：“M2 表里 1pxn 从 0.126 → 0.062，为什么说性能无收益？”
> 受控实验后确认：**用户观察正确，我此前判定归因错误。**

## 决定性实验（同构建只切存储类型）

在含全部 Q4-8 修复的构建上，仅把 m_data 在 __half/flo 间切换并重编：

```
FP32 存储：K2 = 0.064 / 0.062 / 0.063（三跑）
FP16 存储：K2 = 0.062（M2 冒烟值）
```

**完全相同** —— FP16 存储对 k2 无影响（grid 12MB 常驻 L2，命中时
读写无带宽差，与原分析一致）。

## 那 0.126 → 0.062 的 -50% 是谁带来的？

时间线还原：M1 冒烟（0.126）跑在 **Q4-8 屏障修复之前**的构建上；
M2 冒烟（0.062）在**修复之后**。中间唯一性能相关改动 = **Q4-8 的
3 个 __syncthreads 屏障 + 着色同步 + atomic RMW**。

**-50% 的真实来源 = Q4-8 的屏障修复**：barrier1（set_update 写
m_coords → GRID 读 m_coords 之间的 barrier）消除了落后线程写与
其他线程读的交错停顿——正是 ncu long_scoreboard 21% 的主要成分。
屏障补齐后管线畅通，k2 直接减半。
