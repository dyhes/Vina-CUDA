# Q6-IR 设计文档: 混合精度迭代重置 (Mixed-Precision Iterative Reset) — 2026-09-12

> 用户指令: 尝试"混合精度迭代：每 N 步做一次 FP32 精确重置"，先进行
> design-first 立项 + 独立文献调研。
>
> 背景: Q5 (cd10ca24) E1/E1v2 实证排除 FP16 坐标存储(搜索破坏)，
> 但用户放宽了约束: "轨迹分叉可接受，只要 RMSD/affinity 不显著劣化"。
> 在此前提下，重新审视 FP16 的可行路径。

## 〇、核心思想

**不在整个 BFGS 期间用 FP16 状态，而是将 BFGS 迭代分为两个交替阶段**:

```
Phase A (FP16 fast phase): 连续 N 步用 FP16 存储 m_coords/minus_forces/g
                           → 每块 shared 减半(12684→~7000B)
                           → shared 允许 13-16 块/SM → warps/SM 从 14→28-32
Phase B (FP32 reset): 每 N 步做一次 FP32 精确重算
                      → 消除 FP16 累积误差
                      → 恢复 FP32 共享占用(仅此 1 步)
```

预期收益来源:
- 13-16 blocks/SM × 2 warps = 26-32 warps/SM (vs Q5 的 14)
- 大配体上已有 -17% k2 (64t @ 7 blocks)，再翻倍 warps 可能再 -15~25%

## 一、文献调研

### 1.1 混合精度迭代精化(Mixed-Precision Iterative Refinement) — 核心范式

**Haidar et al. 2020** (Royal Society A / ICL-UTK):
- FP16 TC 做 LU 分解，FP64 做迭代精化循环
- 在 Volta GPU 上 4-5× 加速，**FP64 级数值稳定性**
- 关键洞察: **低精度用于"大计算量"部分(O(n³))，高精度用于"校正"部分(O(n²))**
- 与本方案的关系: BFGS 的"大计算量"部分 = E() 评估(占 88%)，
  "校正"部分 = 方向更新 + 收敛判定(O(n)，<5%)
- **映射**: E() 的坐标输入用 FP16，方向更新和收敛判定用 FP32

**Higham et al. 2021** (Multistage Mixed Precision Iterative Refinement, arXiv:2107.06200):
- 三精度方案: 分解精度 u_f、工作精度 u、残差精度 u_r
- 核心理论: 只要条件数 κ(A) < u_f⁻¹ · u_r/u，迭代精化可以恢复高精度
- **关键条件**: 低精度精度 u_f 决定了能处理的最大条件数
- 映射: BFGS 的"条件数" = 能量面的 curvature ratio —
  对接问题中 Hessian 条件数中等(平滑 surface)，FP16 应该够

**Mixed precision Newton's method (arXiv 2607.04828, 2026)**:
- 直接研究 Newton/quasi-Newton 方法的混合精度
- 结论: "低精度梯度 + 高精度方向更新"在条件温和时有收敛保证
- **这是与我们场景最直接对应的论文**

### 1.2 分子对接中的 FP16 精度 — 先例

**Schieffer et al. (AutoDock-GPU TC, arXiv 2410.10447 / 2607 论文)**:
- 将 AutoDock-GPU 的**评分归约**从 FP32 降到 FP16(通过 Tensor Core)
- 结果: 4-7× 加速，** docking 精度无损失**
- 关键: 他们只降了**评分计算的中间累加精度**，没有降坐标/梯度
- 与本方案的区别: 他们不改 optimizer 状态精度

**PETSc/TAO L-BFGS (arXiv 2608.00196)**:
- 通用 L-BFGS 在 GPU 上: 两循环在 FP32，不降精度
- 原因: L-BFGS 两循环的中间量(|g|/|s| 比率)对精度敏感
- 结论: "如果要混合精度，需要配合迭代精化"

### 1.3 重启类方法 — BFGS 的"周期性重置"

**L-BFGS 本身就是"周期性重置"的典型**:
- 经典 L-BFGS 保持 m 对 (s,y) 历史，每步更新
- 当 m 对过旧(> m 步前) → 丢弃 → **等效于部分重置**
- RILC(我们的代码)只保留当前对 → **已经是每步完全重置**

**文献中的 BFGS 重启策略**:
- Powell (1976): 每积累 n 步后重置 H = I
- Nocedal: L-BFGS 的 m 参数控制历史深度
- GPU 实现: 精度重启(每次精度降低后做一次高精度校正)类比 —
  但文献中没有人在 **GPU 对接 BFGS** 中做过精度交替

### 1.4 值域分析: FP16 在分子对接中的适用性

| 量 | 实际范围 | FP16 范围 | 溢出风险 | 精度 | 9.8e-4 相对误差 |
|---|---|---|---|---|---|
| 坐标(盒中心相对) | ±11.25Å | ±65504 ✓ | 无 | 0.0078Å 步长 | 0.0078/11 = 7e-4 |
| minus_forces/梯度 | O(10⁰-10³) | ✓ | 无 | 3e-4 × O(10²) | 值域内精度充分 |
| 能量(affinity) | -15 ~ +40 | ✓ | 无 | — | — |
| 四元数 | [-1,1] | ✓ | 无 | ~1e-3 | 旋转误差 ~0.06° ✓ |
| Hessian 相关(s/y) | O(stp×grad) | ✓ | — | — | — |

**溢出核查完成**: 所有对接量在 FP16 范围内。
**E1 失败的根因不是溢出**，而是坐标量化(0.0078Å)对梯度计算的
噪声注入(δg ≈ Hessian × δx ≈ 0.04)。混合精度迭代重置可以容忍
这种噪声(见 §1.1 的理论: 只要噪声 < 校正精度)。

### 1.5 关键文献结论 → 对 Q6-IR 的启示

1. **Haidar 的分离原则**: 计算精度和校正精度可以不同 → 
   E() 在 FP16 坐标上计算(快) + 方向更新在 FP32(准确) = 正确分工
2. **Higham 的条件数约束**: FP16 精度 u_f=4.9e-4，对接能量面的
   curvature ratio 适中 → FP16-IR 应该收敛
3. **Schieffer 的先例**: FP16 评分在分子对接中已验证安全 → 
   FP16 坐标的误差量级(0.0078Å)与 FP16 评分误差同量级
4. **牛顿法的精度自适应** (2607.04828): "early iterations at low precision,
   precision increased as converging" → 映射: FP16 前期(Far from minimum),
   FP32 后期(Near minimum)

## 二、设计

### 2.1 两阶段交替(Phase A/B)的精确定义

```
Phase A (FP16 fast, N_A 步):
  - m_coords, minus_forces: __half (shared 减半)
  - x, g, candidate: FP32 (不变 — 方向更新精度)
  - p_eval_deriv: FP32 (预计算表, 不变)
  - RILC 方向更新: FP32 (不变)
  - LS(Armijo/curvature): FP32 计算(输入从 FP16 转换)
  - shared: ~7,100B → **13 blocks/SM** (26 warps)

Phase B (FP32 reset, 每 N_A 步执行 1 步):
  - m_coords, minus_forces: flo (恢复 FP32)
  - x, g: FP32 (不变, 本来就是)
  - RILC 方向更新: FP32
  - 本步 E() 完全 FP32
  - shared: 12,684B → 7 blocks (临时回降)
```

### 2.2 关键实现挑战

1. **shared 容量动态切换**: CUDA 不支持运行时改变 __shared__ 大小。
   解决: 用 `extern __shared__` + 动态共享大小, Phase A 分配小,
   Phase B 请求大 → **不可行** (CUDA 要求 launch 时确定)。
   
   **实际方案**: 预分配 Phase B 大小(12684B), Phase A 时只用前半,
   剩余浪费 → 但块数按 12684+1024=13708 → 7 块 → **没有 occupancy 增益!**
   
   **修正方案**: **双 kernel 交替** — Phase A 用一个小 shared 的 kernel
   (7100B → 13 块), Phase B 用一个大 shared 的 kernel(12684 → 7 块)。
   MC 外循环每 N_A 步启动一次 Phase B kernel, 其余是 Phase A kernel。
   Kernel 启动开销 ~10µs, 每 N_A=5 步一次 → 可接受。

2. **状态传递**: Phase A 结束时 m_coords (FP16) → Phase B 需要读它
   (可从 __half 转换) → Phase B 写 m_coords (FP32) → Phase A 再读。
   需要 m_coords 有 FP32 和 FP16 两个副本, 或用同一 buffer 的不同解读。

3. **x (构象) 保持 FP32**: output_type_cl (FP32) 不降精度 → 方向更新
   和 metropolis 不受影响。

### 2.3 修订设计: 双 kernel 交替方案

```
Kernel A (FP16, shared 7100B, 13 blocks/SM, 26 warps):
  - 输入: x (FP32, global→shared), 前一相位 m_coords (FP16→FP32→使用)
  - m_coords, minus_forces: __half shared
  - N_A 次 BFGS 迭代(E+LS+RILC), 但 E 的坐标来源是 __half
  - 输出: 最新的 x, g (FP32, 经 __half2float)

Kernel B (FP32, shared 12684B, 7 blocks/SM, 14 warps):
  - 每 N_A 步执行 1 次
  - 输入: x (FP32, 从 Kernel A)
  - m_coords: flo shared (从 x 重算, 消除 FP16 误差)
  - 1 次 BFGS 迭代(E+LS+RILC), 完全 FP32
  - 输出: x, g (FP32) → 回 Kernel A

MC 外循环:
  for step in 0..search_depth-1:
    mutate(candidate)
    if step % N_A == N_A-1:
      candidate = kernel_B(candidate)   # FP32 重置
    else:
      candidate = kernel_A(candidate)   # FP16 快速
    metropolis_accept
```

### 2.4 对接场景的特殊考虑

- **search_depth = 8**: MC 外循环只有 8 步。如果 N_A = 4 → 每 4 步
  一次 FP32 重置 → Phase A 只跑 3 步 + Phase B 1 步 → 收益比 = 3/4
- **episodes = ~12/轨迹**: 每 episode = ~3.5 BFGS 迭代 + ~4.5 LS trials
  → 每 episode ~19 次 E()。Phase A 中 E() 的坐标从 FP16 读取 →
  每次 E 的插值结果有量化噪声 → BFGS 迭代间噪声不积累(每次 E 独立)
  → **BFGS 迭代内不积累误差, 但 episode 间 m_coords 会**
- **E1 教训回看**: E1 的失败是因为 FP16 坐标贯穿整个 episode(~3.5
  迭代)。混合精度方案中 FP16 只持续 N_A=3-4 个 episode, 然后 FP32
  重置 → 噪声不跨 episode 积累

### 2.5 预期收益与风险

| 维度 | 预期 | 依据 |
|---|---|---|
| warps/SM (Phase A) | 26 (vs Q5 的 14) | 13 块 × 2 warps |
| k2 (Phase A only) | -10~15% | 大配体 E 并行段加速 |
| **整体 k2** | **-5~12%** | 取决于 N_A:Phase_B 比例 |
| 精度风险 | 低-中 | FP16 噪声在 Phase B 重置 |
| 实现复杂度 | **高**(双 kernel + 状态传递) | 主要工程挑战 |
| CUDA 约束 | 无(常规 kernel 交替) | |

### 2.6 备选方案: 不拆 kernel, 用 FP32/FP16 双 buffer

```
__shared__ flo m_coords_f32[MAX_ATOMS][3];    // FP32 正本(始终维护)
__shared__ __half m_coords_f16[MAX_ATOMS][3]; // FP16 影子(Phase A 用)

Phase A: 读 m_coords_f16 (FP16 精度), 写回 f16 + 同步更新 f32
Phase B: 读 m_coords_f32 (FP32 精度)
```
- shared 增加 f16 影子 +768B → 12684+768+768(forces)= 14220 → **7 块不变**
- **没有 occupancy 增益** → 不可行

### 2.7 结论: 必须走双 kernel 交替路线

唯一能获得 occupancy 增益的方案 = Phase A 用小 shared 的 kernel。
这意味着:
1. 把 rilc_bfgs_update 分为 kernel_A 版(用 half m_coords)和
   kernel_B 版(用 flo m_coords)
2. MC 外循环在两个 kernel 间切换
3. kernel 启动开销 ~10µs × search_depth/N_A 次 ≈ 20µs(可接受)

**但注意**: 当前架构是 1 kernel = 1 个 MC step = 1 次完整 BFGS episode。
拆分后 = 每 step 一次 kernel 启动(无论 A 还是 B)。当前已经是这样
(kernel2_update 含完整 MC 循环)。如果拆成 A/B 交替, 需要**重构 MC 
外循环到 host 端**(kernel 启动 N 次)或**用 cooperative groups**
(在 kernel 内做全局同步以切换阶段)。前者增加 kernel 启动开销,
后者需要 CUDA 9+ cooperative launch。

**工作量评估**: 这是一个**架构级重构**, 预计 2-3 个会话。设计
复杂度远超 Q4/Q5 的单变量改动。

## 三、最终建议

**建议将此作为 Q6 方向立项, 而非在 Q5 上继续迭代。**

理由:
1. 双 kernel 交替 = 架构级重构(MC 循环拆出 kernel2_update)
2. 与 S4 系列(同 kernel 内改造)不同, 这是一个**新的编程模型**
3. 需要先验证: 单独的 kernel_A(FP16, 7100B shared, 13 块)的 E()
   精度是否可接受(即 E1 的失败是否可以通过"限制 FP16 步数"避免)
4. 验证顺序: 先做 kernel_A 独立测试(不改 MC 流程), 确认 FP16
   坐标在 N_A 步内不导致发散, 再做双 kernel 交替
