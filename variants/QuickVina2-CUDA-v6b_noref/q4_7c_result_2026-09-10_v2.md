# Q4-7C: pairs prefilter — implemented, weak; execution post-mortem

> Q4-7 execution order per design: A (incremental set_update) → C (pairs
> prefilter) → B (grid gather) → D (evals cut). A and C are now closed.

## 1. A — incremental set_update: REFUTED on math (no code written)

LS trial = `x = xp + stp·d`; BFGS direction `d` is dense (all torsion
components nonzero), and the state chain `q[i] ← q[parent[i]] ⊗ torsion`
propagates every change down the tree → no "unaffected subtree" exists at
any trial step. Incremental coordinate recomputation requires SPARSE
update directions (coordinate-descent style). Check update-vector density
BEFORE designing incremental recomputation for any chained-state kernel —
refuting on paper math before coding cost one paragraph and saved a
multi-day implementation.

## 2. C — pairs prefilter: implemented, kept, but weak

Final form (v2): per-trajectory skip-bitmap in SHARED memory (2048 pairs =
32 u64 = 256 B; total shared 12204+256 = 12460 ≤ 12496 → 8 blocks/SM kept).
bit i set = pair i was beyond cutoff at its last probe; skipped pairs are
re-probed in a rotating 1/8 window (`(i + ep) & 7`), so any pair entering
the cutoff is caught within ≤8 evals. Bitmap zeroed once per kernel via a
bitmap_init latch + zeroed at each kernel_monte entry from the host side.

Result (six-smoke k2 vs Q4-6): 1c5z −5.9%, 1pxn 0%, 3p5o −1.4%,
3b68 −0.4%, 3ag9 −1.1%. MODE1 all in MC-noise band, ERROR=0. Kept
(harmless, marginal gain on big ligands) but FAR below the −10~25% hope.

Why weak: far pairs were already cheap — the skip saves "2 coordinate
loads + 3 mults + 1 compare" per pair per eval, while eval cost is
dominated by set_update (tree walk) + GRID gather (per-atom interpolation)
+ the reduction. The prefilter trims the smallest slice of the eval.

## 3. Execution post-mortem — three failed wirings, then success

v1 (global-memory bitmap): per-pair `atomicOr`/`atomicAnd` on GLOBAL
memory → 3ag9 k2 +88% (L2 atomics cost more than the saved r2 math).
Lesson: a per-pair atomic on every touched pair costs more than the
arithmetic it gates; if the skip is fine-grained, put the bitmap in
SHARED (per-block = per-trajectory is exactly the granularity needed).

v2 wiring failures (each produced compile or illegal-address errors):
- device-symbol cross-TU sharing: nvcc 11.8 without -rdc demotes
  `extern __device__` to per-TU storage → the memset and the reader hit
  DIFFERENT symbols (bitmap never zeroed, pointer never set → address 0x100
  illegal read in compute-sanitizer). Fix: single-TU ownership or pass as
  kernel parameter.
- shared variables are function-scoped: a bitmap declared inside
  `eval_interacting_pairs` cannot be zeroed from `kernel2_update`. Fix:
  declare the bitmap in kernel2_update (which brackets ALL evals) and pass
  it by pointer into eval_interacting; zero it once at kernel start.
- signature threading: adding params to `m_eval_deriv_update` requires
  threading through `rilc_bfgs_update` (which calls it) and both rilc call
  sites in kernel2.cu — with per-site indentation variants (the two
  rilc call sites have different tab depths; the blanket replace matched
  only one).

Process lesson: this implementation went through ~6 failed patch attempts
(compile errors, illegal address, wrong-call-site edits) before landing.
The reverted-state + single-atomic-patch approach (git checkout the file,
apply one verified patch script) is the reliable pattern; incremental
sed-style patching across multiple round-trips is what produced the
tangled state. For multi-signature threading changes, write ONE patch
script that does all edits with per-edit assertions, run it once, verify
brace balance + compile before any smoke.

## 4. Where this leaves LS eval reduction

- A refuted (dense directions), C implemented (weak), B stale (depended
  on A's profile), D (evals cut via initial-step prediction) = changes
  search semantics → Top-1 drift risk, needs multi-run median protocol.
- Q4-6 stands as the engineering+memory-layer ceiling (rt 0.400,
  e2e_dock 0.175, Top-1 177, aff 0.158 = best in series).
- Remaining k2 levers are algorithmic (D) or batch-level (v6 merge).
- C's shared bitmap is kept in the tree (commit ec80715) — harmless and
  marginally positive.
